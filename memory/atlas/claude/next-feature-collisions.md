After the Sorting Layers / Y-sorting / sprite-pivot feature merged into `dev` (2026-07-27), the user's chosen next feature is **static collisions / world solidity**, to be done in a separate session.

Scope discussed (not yet designed): static colliders generated from filled `TileMap` cells (via `@atlasjs/rapier`) + an optional collider on occluder sprites (e.g. a tree trunk), authority `static`. Backlog already lists "Colliders de tilemap".

**Why:** The player currently phases through all decor (trees, pillars, altar) — the Y-sort makes it *look* 3D but you walk through everything. Colliders make the world solid, pair naturally with the Y-sort (pass behind AND bump into the same tree), and are the prerequisite for a real sword-combat loop (the map is `dino_brawl.json`, `SwordScript` already has throw/orbit/power).

**How to apply:** If a session opens on collisions, this is the agreed direction. The physics infra already exists and just needs wiring: `@atlasjs/inertia` (Rapier), `RigidBody2D`, `PhysicsBodyRef`, `PhysicsPushSystem`/`PhysicsPullSystem`, authority-by-body-type. Anchor the collider on the occluder's feet to stay consistent with the pivot model shipped in the Y-sort feature.

**Update 2026-07-27 — audit done + Phase-1 plan written.** A 3-angle sub-agent audit of `inertia`+`rapier` found the collision half is a skeleton that was never wired/exercised, with 3 latent bugs on this exact path: (1) filtering routed to `setSolverGroups` instead of packed `setCollisionGroups`, and `mapColliderDesc` never applies group/mask/userData; (2) raycast ignores unit conversion (wrong ×`unitsPerMeter`=100), `intersectPoint/AABB` are silent `[]`; (3) no collision events, no `Collider.userData`, no gameplay `Collider2D` → nothing collides. Perf blockers (deferred): sleeping killed by push writing all bodies with `wake=true` (no dirty-flag), `new RAPIER.Vector2` per body per tick.

Locked design decisions (brainstorm): named layers per collider (`defineCollisionLayers` in `inertia`, numbers under the hood), Unity-style script callbacks (`onCollisionEnter/Exit`+`onTriggerEnter/Exit`), `Collider2D` without a body = static world geometry, events on by default, contact→entity via `Collider.userData` holding the `Entity`. **The full Phase-1 implementation plan (TDD, per-package, sub-agent-driven) is at [`docs/physics/collision-layer.md`](../../../../Desktop/Node/atlas/docs/physics/collision-layer.md)** — 14 tasks across inertia contract → rapier backend → gameplay wiring → sandbox demo. Deferred to later phases: Phase 0 hygiene cleanup, Phase 2 perf (dirty-flag/command-buffer sync + sleeping), Phase 3 compound tilemap colliders. Execution model agreed: sub-agent-driven, one task at a time, user commits each step (do NOT auto-commit).

Tests: inertia 3/3, rapier 3/3, gameplay 178/178; browser-verified end-to-end under real rapier (onCollisionEnter fired for tree entities).
